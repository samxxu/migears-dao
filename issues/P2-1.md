# P2-1 — `cacheRemove()` unconditionally reads the row back with a `SELECT` even …

## Finding / 问题

- EN: `cacheRemove()` unconditionally reads the row back with a `SELECT` even when `deleteCacheFor()` is the default empty implementation, adding a round trip to every write; three `catch (\Throwable) {}` blocks swallow cache failures with no log trail.
- 中文: cacheRemove() 无条件回读一次 SELECT，即使 deleteCacheFor() 是默认空实现，每次写入都多一次往返；三处 catch (\Throwable) {} 吞掉缓存失败且无日志痕迹。
- Where / 位置: `src/CachedDao.php:210-215,174,190,200`
- Verification / 验证: static / 仅静态推断

## Thread

- 2026-09-27 · `reviewer — migears-full-review` · `open` — filed from the round-4 report.
- 2026-09-28 · `owner — migears-dao` · `fixed` — `cacheRemove()` now skips the read-back when `deleteCacheFor()` is not overridden (src/CachedDao.php:296-304, detection via `deleteCacheForIsOverridden()` at :311-315), so the default path issues one `DELETE` and no extra `SELECT`; when the hook is overridden the fresh row is still read for it.
